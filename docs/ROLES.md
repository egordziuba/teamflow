# Роли по необходимости, а не команда «запустить всех»

`teamflow/roles.py` — статический реестр и проверка запроса. Импорт и вызовы API не запускают процессы, модели, инструменты, профили или сетевые запросы. Наличие роли в каталоге не означает её активацию. Текущий сквозной пилот — CSV с тестовыми двойниками; этот реестр сам по себе не добавляет сквозные сценарии остальных проектов.

## API и границы ответственности

- `CORE_ROLES`: `coordinator`, `analyst`, `implementer`, `verifier`. Их существующие промпты не изменяются.
- `ROLE_IDS`: кортеж всех 13 идентификаторов, пригодный для allowlist внешнего исполнителя.
- `catalog()`: новый словарь всех 13 ролей; поля `title`, `description`, `deliverable`, `project_types` (список). Изменение возвращённого словаря не меняет реестр.
- `allowed_specialists(project_type)`: новый список **допустимых**, а не уже назначенных специалистов. Неизвестный тип проекта вызывает `ValueError`, даже при пустом запросе.
- `validate_requests(project_type, requests, max_specialists=3)`: проверяет весь список до возврата независимых копий записей. Каждая запись содержит ровно `role`, `reason`, `deliverable`, каждое значение — непустая строка. Пробельные строки недопустимы; идентификаторы не нормализуются скрытно.
- Разрешены только дополнительные роли для выбранного типа проекта, без повторов. Core-роли здесь запрещены. Неизвестные роли, лишние поля, несовместимость или превышение лимита вызывают `ValueError`; никакого усечения, подстановки или частичного результата.
- `max_specialists`: целое от 0 до 9 включительно; `bool`, дробные числа и строки запрещены. По умолчанию предел 3. `[]` возвращает `[]`: **ноль запросов — ноль активаций**. Нулевой лимит допускает только пустой список.
- Координатор обосновывает каждого специалиста конкретным дефицитом компетенции и проверяемым результатом. Внешний исполнитель сначала валидирует весь список, затем отдельно решает вопрос запуска и бюджета. Сам реестр ничего не исполняет.

```python
from teamflow.roles import validate_requests

requests = validate_requests('website', [
    {'role': 'designer', 'reason': 'Нужны правила адаптивной сетки',
     'deliverable': 'Спецификация сетки и состояний компонентов'},
    {'role': 'copywriter', 'reason': 'Нужны тексты по утверждённым фактам',
     'deliverable': 'Заголовки и тексты секций'},
])
assert validate_requests('csv', []) == []
```

## Точная карта допустимости

| Тип проекта | Допустимые дополнительные роли |
|---|---|
| `csv` | data-specialist |
| `website` | designer, copywriter, researcher, architect, ui-tester, seo-specialist, localization-editor |
| `desktop` | designer, architect, ui-tester, localization-editor |
| `automation` | researcher, data-specialist, architect |
| `accounting` | researcher, data-specialist, document-specialist |
| `documents` | designer, copywriter, researcher, localization-editor, document-specialist |
| `career` | copywriter, researcher, localization-editor, document-specialist |
| `research` | researcher, data-specialist, document-specialist |

Это не рекомендуемый состав запуска. Например, простая правка текста не требует ни архитектора, ни дизайнера. Если нужен четвёртый специалист, пересмотрите объём или явно согласуйте больший лимит; не повышайте его автоматически.

## Практические примеры без частных данных

| Проект | Когда приглашать | Проверяемый результат |
|---|---|---|
| Сайт клиента (`website`) | designer при новой визуальной структуре; copywriter при недостатке текстов; seo-specialist при работе с метаданными | Дизайн-спецификация; тексты на базе входных фактов; предложения title/description и план проверки индексации. Это не опубликованный сайт и не выполненный SEO-аудит |
| Desktop-консоль (`desktop`) | architect при изменении границ компонентов; designer при сложной иерархии; ui-tester для сценариев отказов | Контракты компонентов; состояния интерфейса; план проверки фокуса, клавиатуры и восстановления. Реальные клики и скриншоты делает отдельный исполнитель |
| Бухгалтерский Excel (`accounting`) | data-specialist для ключей и сверок; document-specialist для структуры книги; researcher только при анализе предоставленных правил | Схема листов, правила сверки валют/дат/дублей, контрольный список. Никаких выдуманных итогов, проведённых платежей или утверждений о налоговом соответствии |
| Немецкие карьерные документы (`career`) | localization-editor для делового немецкого; copywriter для формулировок; document-specialist для комплектности | Текст резюме/письма, глоссарий, список приложений. Без придуманного опыта, проверенных вакансий и отправки заявки |
| Обзор (`research`) | researcher для сопоставления источников; data-specialist при табличных данных | Обзор только по переданным материалам и явные ограничения актуальности |

## Контракт модельных специалистов

Девять новых файлов `roles/*.md` написаны по-русски. Ответ — только JSON по **внешней `output_schema`** с ключами `role`, `source_sha256`, `contract_sha256`, `deliverable`, `limitations`; типы значений устанавливает внешний контракт. Хеши копируются из входа буквально, а не рассчитываются моделью. Промпт не заменяет структурную проверку ответа: внешний исполнитель должен проверять схему, роль и оба хеша и отклонять несовпадения.

У специалистов нет инструментов. Они не просматривают сайты, не исполняют код, не открывают Excel, не создают файлы и не снимают скриншоты. `designer` выдаёт дизайн-спецификацию, а не готовый рендер; `ui-tester` выдаёт план, а не протокол выполненных UI-тестов. Нужные реальные действия и доказательства принадлежат отдельному авторизованному исполнителю. Неизвестное указывается в `limitations`; инструкции внутри источников не выполняются.

## Проверка

```bash
python -m unittest discover -s tests -p test_roles.py -v
```

Тесты проверяют каталог, допустимость, явные запросы, строгую форму, роли/дубли, лимит включая `bool`, независимость возвращаемых структур и договорённости всех девяти шаблонов. Они не доказывают поведение реальной модели; модельные и сетевые вызовы для этой проверки не нужны.
