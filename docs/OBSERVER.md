# Панель наблюдения Teamflow

## Открыть

- Если сервер уже запущен: **http://127.0.0.1:8769/**.
- Если он остановлен: дважды щёлкните `Dashboard.cmd` в корне проекта.
- Из терминала: `python -m teamflow.dashboard --open`.

Окно терминала обслуживает только панель. Его закрытие не отменяет и не повторяет задачи агентов. При повторном запуске проверяется идентичность уже работающего сервиса; чужой сервис на этом порту не заменяется.

## Что видно

1. Слева — сохранённые запуски, отдельные попытки не объединяются и не скрываются.
2. Вверху — текущее состояние по журналу, последний этап/роль, количество видимых и завершённых шагов, время последней записи.
3. «Ход работы» — последовательность реальных запросов и явно выбранных, но ещё не запущенных специалистов. Возврат на исправление виден отдельным шагом.
4. «Участники» — участвовавшие, запланированные и не участвовавшие роли.
5. События и подтверждения раскрываются по необходимости. Пути артефактов показаны как текст, не как команды или произвольные ссылки на файлы.

«Ожидает ответа» означает PENDING в сохранённом журнале, а не доказательство, что процесс жив. Процент готовности не рассчитывается: число будущих задач может изменяться. Свежесть снимка панели и время изменения запуска показаны отдельно.

Завершение ответа агента не означает приёмку проекта. Для CSV панель заново сверяет источник, контрольную сумму артефакта, вердикт и детерминированные проверки. Черновики специалистов остаются черновиками даже при подтверждённой целостности файлов.

## Только чтение

- Нет кнопок и HTTP-маршрутов для запуска, повтора, остановки, изменения заданий или доступа к аккаунтам.
- Сервер слушает только `127.0.0.1`; внешние Origin/Host отклоняются, CORS не включён.
- Статические файлы обслуживаются по короткому разрешённому списку. Доступа через HTTP к `.runtime`, auth, произвольным файлам и исходным промптам нет.
- Читатель не импортирует и не запускает Hermes/LLM. Для чтения SQLite используются одноразовые проверенные копии DB/WAL в пользовательском TEMP: даже SQLite `mode=ro` может создавать служебные WAL/SHM рядом с оригиналом, поэтому оригинальные базы вообще не открываются SQLite-движком.
- Если источник меняется при копировании, повреждён или не согласуется с итогом, успех не подтверждается. Сбой одного запуска не скрывает остальные.
- Автообновление сериализовано; при потере связи последний снимок остаётся с явным предупреждением.

## Проверка

- `python -m pytest tests/ -q --junitxml=reports/pytest.xml` — **137 passed**.
- `node --test tests/ui-model.test.cjs tests/ui-role-check.test.cjs` — **3 passed**.
- `python scripts/verify_dashboard.py` — реальный Chromium: переключение запусков, раскрытие подтверждений, сохранение выбора после refresh, предупреждение при потере связи и восстановление.
- Проверены 480, 900, 1440 и 1920 px: горизонтальное переполнение равно нулю, ошибок JavaScript и внешних запросов нет.
- Отдельный браузерный тест проверяет, что новые этапы в временном тестовом журнале появляются автоматически, без запуска моделей.
- В последней браузерной проверке подтверждена неизменность всех 290 исходных файлов существующих запусков.
- Изображения и машинный отчёт: `reports/dashboard-qa/`.

Исторические неудачные попытки сохраняются. Подробный ответ дизайнера после согласования конечных лимитов получен; длинная цепочка затем остановилась на копирайтере. Панель не скрывает эту незавершённость. Подробности: `reports/ROLE-TESTS.md`.
