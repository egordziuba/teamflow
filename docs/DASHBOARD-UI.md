# Dashboard UI — журнал команды

## Файлы и подключение

- `teamflow/ui/index.html` — русскоязычная оболочка, без inline JS/CSS.
- `teamflow/ui/app.css` — тёмная тема, адаптивная компоновка.
- `teamflow/ui/ui-model.js` — чистые функции выбора запуска и подписей (`globalThis.TeamflowModel`).
- `teamflow/ui/app.js` — DOM, раскрытие разделов, чтение снимка.
- `tests/ui-model.test.cjs` — Node built-in test runner, зависимостей нет.

**Сервер должен отдавать `/ui-model.js` с JavaScript MIME наряду с `/app.js`, `/app.css` и `/`.** В index оба скрипта подключены через `defer` в порядке model → app. Это обязательная часть интеграции, не только файл для тестов. Нужен same-origin GET `/api/snapshot`; CSP достаточно `script-src 'self'; style-src 'self'; connect-src 'self'`. Без сервера/file:// UI не предназначен для работы.

## Поведение

- Единственное сетевое действие — GET снимка. Нет запуска, остановки, повтора задач, POST или открывания файлов.
- Выбор по умолчанию: самый свежий `blocked` по `updated_at`, иначе самый свежий запуск. Существующий выбор сохраняется, даже если появился новый блокер; исчезнувший выбор заменяется по тому же правилу. Даты отсутствующих обновлений считаются самыми старыми.
- Большой заголовок — `current_stage`; статус и пояснение берутся из API. Ровно четыре факта: задача, текущая роль, записанные/завершённые шаги, дата обновления запуска. Нет процентов и утверждений, что процесс жив.
- Шаги и события показаны **в порядке массива API**: сервер должен выдавать хронологический/логический порядок, включая шаги без времени. UI не придумывает этапы, не объединяет повторные роли и не перемещает planned перед реальными событиями.
- Участники разделены на имеющих записи, запланированных, не участвовавших. PENDING — отсутствие записанного результата, не индикатор живого процесса.
- События и подтверждения свёрнуты изначально. Раскрытие хранится отдельно для каждого run id на время жизни страницы. Полная перезагрузка браузера сбрасывает выбор/раскрытие.
- DOM выбранного запуска и список не пересоздаются, если их данные не изменились. При изменении восстанавливается фокус выбранной кнопки/summary. Смена выбора во время fetch не отменяется ответом: актуальный selected id проверяется после получения ответа.
- Один запрос одновременно. `setTimeout` назначается после завершения запроса; период — 3 секунды после ответа. Повторные ручные клики во время чтения схлопываются в один следующий запрос. Тайм-аут запроса — 10 секунд. Ошибка не стирает последний снимок.
- Связь и возраст снимка разделены с датой обновления конкретного запуска. Снимок старше 15 секунд (либо 15 секунд без успешного ответа) помечается устаревшим. Отдельный локальный таймер обновляет только индикатор свежести, без сетевого опроса. Возраст старого завершённого запуска сам по себе не означает потерю связи.
- Пользовательские значения вставляются только как текст (`textContent` / text nodes). Пути артефактов — текст в code, не ссылки. Динамические CSS-состояния ограничены allowlist. Детали сетевой ошибки/сырые ответы не выводятся.
- Никаких демонстрационных fallback-данных: пустой ответ, недоступность и начальная загрузка имеют собственные состояния.

## Компоновка

- Более 1100 px: sidebar 270 px, до трёх карточек шагов в ряд, четыре компактных факта.
- 701–1100 px: sidebar 235 px, вертикальный ход работы, факты 2×2.
- До 700 px: список запусков сверху (ограниченная высота с вертикальным скроллом), затем выбранный запуск, карточки вертикально, факты 2×2; header перестраивается.
- Главная область ограничена 1300 px, общий контейнер 1760 px. Длинные id/пути переносятся; используются `minmax(0,1fr)` и `min-width:0`, нет намеренного горизонтального скролла страницы.
- Нативные button/summary, заметный `focus-visible`, skip link к main. `aria-live` только у меняющегося статуса связи, не у всего журнала. Число событий/даты не проговариваются каждые три секунды.

## Выполненные проверки

```sh
node --test tests/ui-model.test.cjs
node --check teamflow/ui/app.js
node --check teamflow/ui/ui-model.js
```

Node v22.23.1. Два тестовых сценария проходят: выбор/сохранение/исчезновение выбранного запуска/пустой список и семантические подписи/честный PENDING. Каждый сценарий сначала запускался RED из-за отсутствующей соответствующей функции, затем GREEN. Проверка синтаксиса проходит. Автоматический lint write/patch ошибочно преобразует Windows-путь в `C:\c\Users\…`; прямой `node --check` из каталога проекта проходит.

## Обязательная независимая browser QA

Браузер и сервер этим исполнителем **не запускались**, скриншотов нет. CSS и поведение браузера не объявляются визуально проверенными. Родительскому исполнителю проверить реальный сервер:

1. `/ui-model.js` доступен, MIME верный, CSP не блокирует скрипты, console чиста.
2. Viewports 480 / 900 / 1440 / wide: `document.documentElement.scrollWidth <= innerWidth`; длинные пути и повторные попытки читаемы, последняя карточка и evidence доступны.
3. Keyboard Tab/Enter/Space: выбор, обновление, оба disclosures; focus не пропадает при poll. Read-only заголовок и статусы разборчивы.
4. Выбрать другой запуск во время задержанного GET: поздний ответ не возвращает старый выбор. Раскрыть раздел, дождаться обновления, переключить запуск и вернуться.
5. Несколько быстрых обновлений при задержанном GET: максимум один запрос одновременно, максимум один накопленный ручной refresh.
6. Прервать доступ к API после успеха: последний снимок остаётся и явный баннер предупреждает об устаревании. Восстановить API: баннер исчезает. Проверить отсутствие данных и первичную ошибку отдельно.
7. В изолированном тестовом ответе строки с HTML должны отображаться как текст; artifact path не становится кликабельным URL. Не подменять реальный журнал демоданными при приёмке.

Unit-тесты не доказывают визуальную адаптацию или браузерную race-safe работу; это отдельный gate.
