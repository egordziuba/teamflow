# Hermes Project Team — локальный пилот

## Цель
Четыре независимые роли (координатор, аналитик, исполнитель, проверяющий), версионирование контекста, ограниченные циклы исправления, независимая приёмка и восстановление после прерывания.

## Граница первого этапа
Агенты работают без инструментов и возвращают JSON. Управляющий код проверяет ответы, вычисляет факты детерминированно и сохраняет артефакты. Модельный код никогда не исполняется. Нет доступа к почте, платежам, рабочим сайтам; нет обновлений Hermes или изменений основного профиля. Kanban используется в отдельном runtime, не обслуживаемом основным gateway.

## Испытательный сценарий
Контроль качества импорта небольшого CSV с операциями в EUR. Источник содержит разделитель `;`, десятичную запятую, дубликат и некорректную строку. Исходная рабочая гипотеза о разделителе неверна. Гипотеза может быть исправлена, цель и приёмочные правила — нет. Контролируемая дефектная кандидатная версия используется только как маркированная тестовая инъекция для проверки отказа и повторной работы.

## Готовность
- Автоматические тесты защитных правил и восстановления.
- Реальные вызовы Hermes по ролям, без подстановки вымышленных ответов.
- Независимая проверка точной версии артефакта.
- Отказ до исправления; успешная приёмка только после фактических проверок.
- Документированная команда запуска и журнал результатов.
